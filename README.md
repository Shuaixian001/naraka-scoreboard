# 永劫无间赛事积分表

[English](README.en.md) | 中文

一个**零依赖、纯前端**的《永劫无间》赛事积分表，支持**中文 / 英文界面**。主页面是单个 `index.html`，BP 英雄头像放在 `assets/heroes/`，官方队标放在 `assets/logos/`，评级素材放在 `assets/weapons/`、`assets/players/`；双击 `index.html` 就能用，不用装任何东西，不用联网。线上版可选接入腾讯云 CloudBase，提供公开赛事库和会员在线编辑。

## 在线使用

**https://jiestandings.com/**

线上页面默认打开「公共赛事」页：左侧是按标签分组、可收起的历史赛事目录，右侧是实时积分榜，访客只读；每个公开赛事都有独立分享链接。点顶栏「本地计分台」进入自己的本地工作区（也可以直接访问 `#local`），新建 / 导入的数据只存在你自己的浏览器里，不会上传到任何服务器。

公开赛事库需要管理员在 CloudBase 里配置，见下方[公开赛事库与会员编辑](#公开赛事库与会员编辑可选)。没有配置时，页面就是一个纯本地工具；双击本地文件也会直接进入本地计分台。

## 功能

### 赛制

- **积分制**：`总积分 = 排名分 + 击败分`
- **赛点制**：可配置赛点分数（默认单排 16 / 三排 36）与最大局数（默认 8 局）
  - 实时标记谁已开启赛点，带进度条显示还差多少分
  - 开启赛点后再拿到一次单局第一即自动判定夺冠
  - **赛点排名分**：开启后自下一局起每局递增（单排 +0.5 / 三排 +1），可开关
  - 打满仍无冠军则按总积分定冠军
  - 达阈当局取胜是否算夺冠可配置（官方规则为「**再**获得一次」，默认关）

### 对局类型

- **天人对局**：排名分 + 击败分，用天人排名分表
- **武道对局**：只有排名分，用独立的武道排名分表，没有击败分输入框
- 每局的类型可在录入界面随时切换；单排新建赛事的第一局默认是武道，三排默认全部是天人对局（也可以手动改成武道）

### 地图天气

- 每局可记录地图与天气，显示在对局卡片和积分榜的表头提示里
- **武道**固定为火罗国；**天人**可选 14 种：聚窟州（早晨/正午/黄昏/夜晚）、
  火罗国（黄昏/阴天/晴天/星夜）、龙隐洞天（日暮/夜半/朝露）、宛渠（夕阳/烈日/星夜）
- 带萤火虫的天气在地图名后会标「**（虫）**」（英文版对应 Fireflies），一眼区分开
- 新建赛事后连加对局会自动排好地图天气：
  - **单排**：第一局 武道·火罗国 → 聚窟州·早晨 → 火罗国·阴天 → 龙隐洞天·朝露 → 聚窟州·正午 →
    火罗国·星夜 → 龙隐洞天·夜半 → 聚窟州·夜晚
  - **三排**：默认没有武道局，从 聚窟州·早晨 → 火罗国·阴天 → 龙隐洞天·朝露 → 聚窟州·正午 →
    火罗国·星夜 → 龙隐洞天·夜半 → 聚窟州·夜晚（共 7 局）
  - 两种模式都可以随时把某一局切换成武道；预设之外的对局不自动配地图，自己选

### 积分构成

`总积分 = 前序积分 + 武道对局积分 + 天人对局积分`

- **前序积分**：每个参赛者可直接填一个带入分，计入总积分，也参与赛点开启判定
- 前序分不计入单局得分（单局第一仍按当场所得比较）

### 分组（小组赛）

- 每个参赛者归属一个组（A/B/C…），每局可选择参与组（单组 / 跨组 / 全员）
- 积分榜可切「合并总榜」或各组榜；组榜只是行过滤 + 组内重排，分数口径与总榜一致
- 支持随机平均分组、组改名（自动同步所有引用）、批量按 `[A] 队伍名` 前缀建组

### 赛区标签

和分组相互独立的一套标记，用来区分赛区、分部、战队归属之类。

- 标签名完全自定义，每个标签**可以单独配色**（新建时自动从 12 色调色板取一个没被占用的颜色，
  点标签前面的小色块随时改）
- 积分榜会多出一列「赛区」，夹在**组**和**队伍 / 选手**之间，显示成彩色小标签
  （底色用标签色，文字按对比度自动配黑/白）；没人打标签时整列自动隐藏
- 参赛者面板每个选手行有赛区下拉；「批量管理 / 删除」弹窗里可以一次给多人打同一个赛区
- 标签可改名（参赛者引用自动同步）、可删除（确认框会写明影响几人）

### 多人规模（8-48 人/队）

- 批量粘贴名单：单排每行一个名字；三排 `队伍名 / 成员1 / 成员2 / 成员3 …`（用 `/` 分隔，**成员数量不限**）
  - **行首可选前缀**：`[A]` 写分组，小括号或大括号写赛区，两者顺序随意、都可有可无
  - 例：`[A] (华东) 队伍名 / 成员1 / 成员2 / 成员3`、`{华东} 选手名`、`（华东）[A] 选手名`
  - 认小括号/大括号的**半角与全角**四种写法；只认行首，名字中间的括号原样保留
  - 遇到新分组/新赛区会自动创建，确认框里会写明
- 参赛者**批量管理 / 删除**：勾选任意多人后，一次把他们归到同一个组（或移出分组）、或批量删除。
  弹窗里可以**就地新建分组**和**新建赛区标签**，不用退出去建
- **一键导入官方战队名单**：参赛者面板「+ 添加官方战队」，从内置名单里挑队伍 / 选手
  - **三排赛事**：每队一条（参赛者名 = 战队名），队员就是该队的三排选手 + 灵活选手，战神点选时直接可选
  - **单排赛事**：一位选手一行，录成 `战队名.选手名`，可以只挑几个人，不必整队
  - 名字写法可切：**官方 ID**（默认，如 `成都Wolves.ZK`）/ **中文昵称**（如 `成都Wolves.扎克`）
  - 已存在的名字自动跳过；原有的批量粘贴、逐行修改等手动录入方式完全不变
  - 内置名单为 **NBPL 2026 秋季赛**的 16 支战队（72 人：单排 17 / 三排 53 / 灵活 2），换赛季需要重新生成
  - 官方队标按赛季放在 `assets/logos/2026FALL_NBPL_LOGOS/`；以后换赛季新建一个目录，旧目录不要移动或改名，历史赛事保存的是完整路径
- 录入网格支持 **Enter / ↑ ↓ / ← → 键盘流**（左右可跨行一路走完整张表）、未录入高亮、跳到未录入、大名单搜索
- 积分榜每局一列，只显示该局总分，**该局最高分自动高亮**
- 积分榜**默认展开全部**，超过 8 人时给「收起」按钮，也可拖右下角手动调高矮

### 实时积分榜

- **显示设置**（标题栏按钮，每个赛事单独一套，跟着赛事导出）
  - **列**：勾选显示哪些列、`←` `→` 调顺序（行聚焦后按方向键也行，↑↓ 等效）、逐列设宽度（留空 = 自动）；
    `排名` 和 `队伍 / 选手` 固定显示
  - 「每局（共 N 列）」整组管：一起显示 / 隐藏、一起移动、统一宽度
  - **单元格**：上下留白 / 左右留白 / 字号三个滑块，拖动即时生效
  - **名次着色**：合并总榜和 A/B/C 分组榜各有一套规则（如 5-8 名标灰），整行上色；分组榜默认沿用总榜，改动后独立，可点「沿用总榜」恢复
  - 改过列宽才切固定布局（超出列宽的内容省略号裁掉）；没动过宽度时外观与以前完全一致
- **简表 / 完整表一键切换**：等价于一键收起 / 展开「前序 + 每局」两列，适合投屏和播报
- **赛点制下夺冠选手立刻置顶**为第一名，其余整体下移一位
- 三排赛事的计数一律按「队」显示，单排仍是「人」

### 每局战神 / 武道冠军

- **天人局**显示本局最高分队伍的战神
  - 单排：就是单局最高分本人
  - 三排：默认显示战队名，点标签弹窗从该队选手里选一名 → 显示成 `战队.选手`
  - 队伍没录成员时用战队名代替；最高分并列时先显示「待裁定」，点它直接跳裁定弹窗
- **武道局**同一位置显示「武道冠军」，只写队名 / 选手名，不选人
- 战神只记「哪支队 + 哪名选手」，队伍按实时比分算：改分导致最高分换队时自动跟随

### 同分排名规则

总分降序固定在最前，其余比较项在「设置 → 同分排名规则」里可增删、改方向、调顺序。

- **积分制默认（单排）**：前序积分升序 → 第一局积分升序 → 击败分降序 → 单局最高分降序 →
  单局最高击败降序 → 最后一局积分降序 → 最后一局击败降序 → 最后一局名次升序
- **积分制默认（三排）**：前序积分升序 → 击败分降序 → 单局最高分降序 →
  单局最高击败降序 → 最后一局积分降序 → 最后一局击败降序 → 最后一局名次升序（不比较第一局积分）
- **赛点制默认**：前序积分升序
- 全部比较项都相同 → 视为并列，在「同分人工评定」里点名字排先后
- 「清空」一键去掉全部比较项（总分相同直接并列）；「恢复默认」回到当前模式的上面这套

### 中英文切换

- 顶栏最右侧的按钮在**中文 / 英文界面**间一键切换，你的选择会记住
- 首次打开跟随浏览器语言：英文浏览器自动显示英文版，中文浏览器保持中文
- 分享链接加上 `?lang=en`（或 `?lang=zh`）可直接指定语言，方便发给海外观众
- 只翻译界面文案；**选手名、赛区标签等数据保持原样**，导出文件不受影响。赛事名、榜单标题和备注可以在计分台里另填英文：英文界面优先显示英文，缺失时回退中文
  （地图名用游戏内英文：聚窟州 Morus Isle / 火罗国 Holoroth / 龙隐洞天 Perdoria / 宛渠 Wanchu；
  「武道」译作 Martial Artist，武道地图显示为 Versus-Random；天气名如 Dusk (Fireflies) / Eventide 等）

### BP 选人（第一版）

- 在「比赛录入」顶部、`+ 添加一局比赛`下方点「BP 分组 / 开始」。进入后先看到「BP 赛前设置」：选好局次、分好组并确认顺位，再点「开始当局 BP」进入正式选人界面；窄屏和手机端也会用整页宽度显示分组、排序和手动录入，不会挤在 BP 界面左栏。武道局不参与 BP。
- 正式选人界面只有中间英雄池（图片下方带英雄名）和右侧栏；右侧栏从上到下依次是「局次」「本局已选」「镜像对局指定」，原来的左侧栏全部移除。窄屏会自动改成纵向排列，英雄池和右侧栏依次向下，不会互相遮挡。分组和顺位工具只在赛前设置显示；比赛中需要调整时点右上角「分组 / 顺位」回到设置，现有已选英雄会保留。
- 单排、三排都支持；点击英雄只进入待确认状态，必须再点「确定选择」才写入，避免误点。三排以整支队伍为单位：选满本队三个英雄后一次确定，选人过程中不会自动跳到下一队。
- 分组板可以选择组数（默认 4 组），把选手/战队卡片直接拖进各组，也可以用「按顺序分到各组」或手动录入；手动分组同样可以作为循环基础。单排积分制且组数为 4 时，会按武道名次预填：第 8 名→1 组、第 7 名→2 组、第 6 名→3 组、第 5 名→4 组，前四名由你拖进对应组；组内按武道名次排序，无排名选手后选。三排组内没有先后顺序。
- 顺位可以按当前积分生成并把赛点选手后置（单排，适合 2–5 局），或按当前积分正序且不区分赛点（单排，适合 6–7 局）。单排和三排都可以用同一套基础分组铺到所有 BP 局：积分制循环组序，赛点制固定 1 2 3 4。排序有两个独立按钮：「按积分排序」只按当前积分排序，「按积分排序（赛点后置）」会再把已经开启赛点的队伍放到最后，与单排的两种排序一致；两个按钮都只排当前局队伍。「按顺序分到各组」只生成当前局分组，切换其他局不会覆盖已经排好的局。需要把一套分组统一生成到所有 BP 局时，点「填充各局」：积分制会按组号循环（如 `1234 → 2341 → 3412…`），赛点制固定 `1 2 3 4`。组号输入框会显示当前局的顺序，可以手动改成 `4 3 2 1` 等再应用到当前局。
- 积分制且可 BP 的对局正好为 5 局时，分组完整并进入 BP 后会自动套用前四局组序 `1234 → 2341 → 3412 → 4123`，并把最后一局标记为镜像对局；先分好组再添加第 5 局也会自动补齐。已有选人记录时不会覆盖；镜像英雄仍需在英雄池中指定。
- 三排英雄池会在英雄右上角显示本次选择的预计英雄分。预选需要英雄分的英雄会立即从队伍可用英雄分中暂扣；可用分不足时该英雄会像单排一样禁用。移除或取消预选会返还暂扣分数，确认后才正式写入。
- BP 规则面板按赛事模式分开：单排赛事只显示单排规则，三排赛事只显示三排规则和英雄分表。
- 新建赛事时按赛制自动选择 BP 预设：积分制默认单排至少 3 名不同英雄、三排起始 0 分；赛点制默认单排至少 5 名不同英雄、三排起始 5 分。两套预设都限制同一名单排选手最多只有 1 名英雄使用 2 局。已有赛事可在 BP 规则设置里切换「积分制预设 / 赛点制预设 / 自定义」。
- 三排英雄分在 BP 规则设置里用表格逐格填写，两列是独立的：
  - **单队第 N 次使用**：同一支队伍当天第 N 次使用该英雄时扣多少分。
  - **同局第 N 次被选加价**：本局该英雄第 N 次被选中时额外加多少分；同一组同时选择，组内不互相加价，后续组按该英雄已完成的选择次数 + 本次查表。

  默认值如下，可直接在表格里改成自己的数值（当前预设到第 6 次，超过第 6 次按第 6 次计算）：

  | 次数 | 1 | 2 | 3 | 4 | 5 | 6 |
  | --- | ---: | ---: | ---: | ---: | ---: | ---: |
  | 单队第 N 次使用 | 0 | 0 | 2 | 3 | 0 | 0 |
  | 同局第 N 次被选加价 | 0 | 0 | 2 | 2 | 2 | 2 |

  例如第一组 A/B 两队同时首次使用胡桃：两队都是 0 分；下一组 C 首次使用胡桃时，前面已经累计 2 次，C 按同局第 3 次加价 +2。如果 C 当天已经用过胡桃两次，则再叠加单队第 3 次的 2 分，合计 4 分。
- 镜像局在 BP 右侧栏底部的「镜像对局指定」里添加：先在「局次」切到目标局，点「+ 添加当前局」；同一个赛事可以添加多个镜像局。点镜像局名称会切回该局，再到中间英雄池点击指定英雄：单排选 1 个，三排选 3 个阵容英雄；每个镜像局右侧的 × 可以取消指定。积分制 5 局的默认预设会自动标记最后一局，仍需手动指定镜像英雄。比赛录入表和公开单局表会按局分别显示各自的镜像英雄或阵容。镜像阵容不会逐个写入普通 BP 选择。
- 右侧「本局已选」按本局 BP 顺位排列，队伍前会标出顺位号。
- 点击比赛表里的已选英雄头像，会以「BP前回看」打开该选手/战队选择之前的 BP 画面，球队/选手最终选的英雄会用金框标出；点「返回当前」可回到实时 BP。
- 有 BP 的对局，比赛录入表和公开单局表会把已选英雄头像放在选手/战队名字右侧，并带金色边框；点击头像会打开对应选手/战队的 BP 界面。
- 完整的 NBPL 自动轮换和镜像英雄自动推荐仍在后续；当前已提供积分制 5 局的分组轮换和最后一局镜像标记默认预设。
- 英雄头像来自 `assets/heroes/`，官方队标来自 `assets/logos/`，评级素材来自 `assets/weapons/`、`assets/players/`；本地使用和部署时都要把这些目录和 `index.html` 放在一起。

### 模拟 BP

- 顶栏「模拟BP」是与公共赛事、本地计分台并列的独立浏览器沙盒，不会写入本地赛事或公开库；数据单独存在当前浏览器里。
- 可以切换单排/三排、设置 1–12 局；从同模式的本地赛事一键添加全部参赛者或打开挑选弹窗，从官方名单添加战队/选手，也可以按行批量添加自定义选手/队伍（三排可写成员）。
- 「带入整场记录」会替换当前沙盒，并把所选本地赛事的全部局次、赛前积分、每局得分、BP 规则、选人记录和镜像局一起带入；超过 12 局时只带入前 12 局。
- 参赛者支持改名、编辑三排成员、单个移除和清空。积分在「记分」里按局填写：有赛前带入列、每局单局得分列和自动累计列；BP 页头的「记分」会直接高亮当前局，方便每局结束后录入。
- 参赛者区的「赛事 / 预设」来源可以选本地赛事或已保存的模拟器预设；「一键添加全部」和「带入整场记录」都支持预设。
- 在「模拟设置」里可以切换积分制/赛点制、设置赛点分，并进入现有 BP 赛前设置做分组/顺位，或修改完整 BP 规则和英雄分表。BP 设置里的「按积分排序」「按积分排序（赛点后置）」会使用当前局开始前的累计积分；赛点制下达到赛点分的队伍会作为赛点队伍后置。
- 点「开始模拟 BP」直接进入现有 BP 工作台；BP 选择、每局积分、镜像局、分组和规则会自动保存在浏览器，刷新或切换页面后恢复。「重置模拟」会清空当前沙盒。
- 可以逐局连续模拟：每局 BP → 用「记分」填当前局得分 → 下一局按累计积分/赛点状态排序；也可以用「带入整场记录」一次性回放本地整场。
- 页面底部的「按战队模拟」可以选择本地赛事或已保存的模拟器预设，再选战队/选手，复制一份预设 BP 后进入战队视角：右上方切换局次，开始时只修改所选战队的英雄，其他战队保持预设。点「重选本局」会保留本局当前组和前面组的 BP，清空所选战队本局选择、本局后续组（含其他战队）以及之后所有局的 BP；随后可以继续模拟这些被清空的战队，方便从分支点重走整段 BP。退出模拟后，修改只留在沙盒，不影响原赛事。
- 战队视图里，英雄池中当前选中战队的原预设英雄会显示金框和「原」标记，方便重选时对照。被清空或改动的战队下方会保留一排不带金框的原预设英雄，自己 DIY 的选择正常显示；「本局已选」不再使用金框。
- 完成 BP 后，BP 卡标题栏里的「保存为预设」会把当前模拟器的全部 BP 保存为一个**有名字**的模拟器预设（只保存在浏览器，不修改本地赛事）。从预设战队模拟保存时，名称默认预填为“原比赛名 · 战队”；从普通模拟保存则预填“模拟 BP · 单排/三排”。名称可以修改，多次保存会生成多个预设。
- 左侧「管理预设」可以查看所有已保存预设，改名、重新模拟（默认带出保存时的战队）或删除单个预设；预设也可以在「预设来源」下拉里直接选择。
- 「本地BP参考」可以按本地赛事 → 对局 → 选手/队伍查看已选英雄，只读展示，不会写入模拟数据。

### 评级板

- 顶栏「评级」是与公共赛事、本地计分台、模拟BP并列的独立本地工具；不会写入赛事或公开库，评级内容只保存在当前浏览器。
- 版式是操作按钮在标题上方，标题居中；评级板在中，待评级区、素材库依次在评级板下方。
- 素材库预设五类：战队队标、英雄头像、武器、单排选手、三排选手；队标和英雄复用现有 `assets/logos/`、`assets/heroes/`，武器和选手来自 `assets/weapons/`、`assets/players/` 与 `assets/materials.js`。
- 默认档位 S/A/B/C/D，可增加、删除（至少保留一个），每个档位文字可以直接改，颜色调整和删除本行在右键菜单里；档位始终紧贴，档位之间用表格式分割线分隔。
- 素材可以重复添加，每次点击都会生成一份新的待评级素材；点素材加入待评级区，再拖进档位。同一档位内可以拖动调整顺序；手机端点选素材后，再点同档位里的目标素材即可插到它前面。选手素材会显示成「战队.选手名」，不再在名字下面单独占一行显示战队。
- 两档之间的分割线也可以放图片：把素材拖到分割线上，素材会保持普通卡片大小骑在线上（上半部分在前一行，下半部分在后一行）。拖到线上的横向位置决定它放在哪一列，拖动时会显示虚线卡片框预览落点；该列会在上下两行留空，已有素材会顺延，不再固定最左或最右。导出图片也保持同样的布局。右键档位可以调整颜色或删除该行，也会提供插入档位的入口；右键分割线可直接插入档位。
- 选手素材可以在素材库里切换显示「中文名」或「ID」；切换后素材库和已放入评级板的选手会一起更新。导出图片时使用生成预览时的显示名，中文页面 + ID 模式不会回落成中文原名。
- 上传入口在待评级区的虚线加号；上传的本地图片会压缩后存当前浏览器 IndexedDB，刷新或切换页面会恢复，换设备或清缓存会丢失，不上传服务器。想改素材名时，直接点素材名称输入新名字即可。
- 点「导出图片」会先用原生 Canvas 生成预览弹窗，确认后点「下载图片」保存整张 PNG（标题、档位、素材和日期）；取消不会生成文件。导出图是白底，标题居中，不再带顶部 NARAKA 标识行；档位自定义颜色和分割线上的图片会同步导出。只导出已加入评级板的素材，未分档的素材会放在「待评级」区。导出需要通过 `localhost` 或线上页面打开；`file://` 直接打开时浏览器会阻止把本地图片画进 Canvas。
- 素材库底部标注图片来源，naraka.wiki 和 narakathegame.com 均为可点击链接，版权归官方所有；网页页脚也注明英雄图片版权，并用图标链接提供联系邮箱和 GitHub 页面。
- 预设素材需要和 `index.html` 一起部署；运行时以 `assets/materials.js` 为准，`assets/weapons_review.csv` 用于校对武器中文名，改完需要重新生成 `materials.js`。

### 批量管理赛事

导入和批量的入口在**顶栏**（「+ 新建赛事」右边）；单个赛事的导出 / 删除仍在「设置 → 数据」：

- **批量导入**：顶栏「导入赛事」一次选中多个 JSON 文件，全部读入后弹一次确认框列出所有赛事名。
  读不了的文件会被单独列出并跳过，不会因为一个坏文件中断整批；同名赛事自动加「（导入）」后缀
- **批量导出**：点顶栏「批量管理赛事」勾选任意多个赛事，两种导出方式
  - *导出为一个文件*：打包成 `{events:[...]}`，之后导入可一次全部还原
  - *逐个导出*：每个赛事一个文件，用各自的赛事名命名
- **批量删除**：同一个弹窗里「删除选中」。确认框会列出完整赛事名；
  全选删除时还会再确认一次。删掉当前正在看的赛事会自动切到剩下的那个
- **调整顺序**：直接**拖动整行**到目标位置（适合长距离），或用行尾的 `↑` `↓` 微调相邻位置；
  顶栏赛事下拉的顺序跟着变，已勾选的不受影响

> **关于「逐个导出」**：浏览器会在开头询问「是否允许下载多个文件」，选**允许**即可。
> Edge 实测会正常提示并下载。如果浏览器默认拦截又不弹提示，
> 改用「导出为一个文件」打包导出更稳妥。

## 公开赛事库与会员编辑（可选）

线上版把界面分成两个视图：

- **公共赛事**（默认）：左侧历史赛事目录（按标签分组，可搜索、按单排/三排过滤）+ 右侧实时积分榜。访客只读；每个赛事有独立分享链接 `#public/<文档 ID>`。
  - 分组标题可以点开 / 收起；收起状态保存在当前浏览器。一个赛事可以属于多个标签，会在每个标签分组里各出现一次，并标注「也在：其他标签」。标签名里用 `/` 可以形成树状目录，例如 `NBPL赛事/2026秋季赛/第二赛段`；没有 `/` 的旧标签仍是一级文件夹。
  - 管理员在目录右上角点「整理」，可以像本地批量管理一样拖动或用 ↑↓ 调整顺序，并给赛事添加 / 移除标签（标签可新建，每个赛事至少保留一个）。整理结果对所有访客生效。
  - 公共页浏览态直接显示只读的「单局积分」卡片：复用录入卡片的布局，每局默认展开、不限高，列出击败、名次、单局得分等完整录入结果；点卡片标题仍可单独折叠该局。标题栏的「收起 ▲ / 展开 ▼」可以整体隐藏 / 显示这块内容。它只在公共页浏览态显示，进入编辑或本地计分台不显示；纯展示，不修改数据。
- **本地计分台**：自己的本地赛事工作区。顶栏「公开赛事」打开同一个目录：发布者选中自己的赛事后会在计分台里打开（带「返回我的赛事」），其他人在公共页只读浏览。
- 计分台设置里可以填写英文赛事名；显示设置里可以填写英文榜单标题；备注编辑框里可以填写英文备注。切换到英文界面时优先显示这些英文内容，没填则回退中文；界面一次只显示当前语言的一份内容，不会双语并排。编辑时当前语言的字段排在前面，另一种语言可选填写。
- 本地文件（`file://`）模式默认进入本地计分台，不连接 CloudBase。

### 权限与隐藏

- **只有发布者本人能修改公开赛事的内容**；其他授权会员只读，但可以发布自己的本地赛事。
- **管理员**可以隐藏 / 恢复 / 删除任何公开赛事，但不能修改别人发布的内容；管理员对自己发布的赛事仍可正常编辑。
- **发布者**可以隐藏 / 恢复 / 删除自己发布的赛事；其他会员只读，不能隐藏或删除别人的赛事。
- 没有编辑权限的人可以打开「显示设置」查看当前配置，但除「完成」外所有按钮和输入项都不可操作。
- **删除是永久操作**：会同时移除公开赛事内容、标签/排序和隐藏状态，所有分享链接失效；本地副本仍保留，不会跟着删除。隐藏则只是让访客看不到，数据继续保留。
- **管理员**还可以整理任何公开赛事的标签和显示顺序。整理只写 `published_event_visibility` 里的 `tags` 和 `order`，不改赛事正文和 `rev`，所以不会和发布者的自动同步冲突。
- 取消公开是**隐藏但保留**：数据仍在 CloudBase，可随时恢复；访客看不到隐藏赛事，发布者和管理员会在目录的「已隐藏」分组里看到。
- 隐藏只是界面过滤，不是严格保密：直接调用数据库 API 仍可能读到隐藏文档，请不要把敏感内容放进去。
- 公开数据只存在 CloudBase 和页面内存，不写入访客的 localStorage；本地浏览器只保存一个轻量链接表（赛事 ID → 公开文档 ID），不含赛事正文。

### 后端配置（一次性）

后端使用腾讯云 CloudBase 文档数据库。

1. 注册腾讯云并完成实名，创建 CloudBase 环境（上海地域），记下环境 ID；把 ID 填到 `index.html` 里的 `const CLOUD_ENV = ''`。
2. 控制台 → 身份认证 → 登录方式：开启**邮箱验证码登录**（发件方式选内置邮件服务）、**邮箱密码登录**和**匿名登录**。匿名登录用于让未登录访客自动获得一个只读会话；匿名用户不在会员白名单里，不能修改数据。
3. 环境配置 → 安全配置 → 安全域名：加入 `jiestandings.com`（需要 www 时再加 `www.jiestandings.com`）；本地调试加入 `localhost:8123`。
4. 创建三个集合：`published_events`（公开赛事内容）、`published_event_visibility`（隐藏状态、标签和排序）、`app_config`（会员配置）。
5. 安全规则都选「自定义安全规则」，不要用默认的「仅创建者可读写」。

   `published_events`：

   ```json
   {
     "read": "auth != null",
     "create": "auth != null && (auth.uid in get('database.app_config.editors').uids || auth.uid in get('database.app_config.editors').admins) && request.data.ownerUid == auth.uid",
     "update": "auth != null && doc.ownerUid == auth.uid",
     "delete": "auth != null && (auth.uid in get('database.app_config.editors').admins || (auth.uid in get('database.app_config.editors').uids && doc.ownerUid == auth.uid))"
   }
   ```

   `published_event_visibility`：

   ```json
   {
     "read": "auth != null",
     "create": "auth != null && (auth.uid in get('database.app_config.editors').admins || (auth.uid in get('database.app_config.editors').uids && request.data.ownerUid == auth.uid))",
     "update": "auth != null && (auth.uid in get('database.app_config.editors').admins || doc.ownerUid == auth.uid)",
     "delete": "auth != null && (auth.uid in get('database.app_config.editors').admins || (auth.uid in get('database.app_config.editors').uids && doc.ownerUid == auth.uid))"
   }
   ```

   `app_config`：

   ```json
   {
     "read": "auth != null",
     "update": "auth != null && auth.uid in get('database.app_config.editors').admins"
   }
   ```

   `published_event_visibility` 的文档除 `hidden` 外还可以保存 `tags`（标签数组）和 `order`（排序数字）。旧文档没有这两个字段时，页面会把 `published_events.folder` 当作唯一标签，不需要迁移。

6. 在 `app_config` 里创建文档 `_id = "editors"`，先填：

   ```json
   { "uids": [], "admins": [], "names": {} }
   ```

7. 部署后打开网页 → 会员登录：新账号在「注册账号」里先填邮箱、发送验证码，再在下一步设置密码；已有账号用密码登录。忘记密码时点密码登录下方的「忘记密码」，验证邮箱后设置新密码；也可以改用「验证码登录」。登录后点「复制 UID」。回到控制台，把该 UID 同时加进 `app_config/editors` 的 `uids` 和 `admins` 数组；`names` 里可以写显示名，例如：

   ```json
   { "<你的UID>": "赛事数据组" }
   ```

8. 重新打开页面并登录，就可以在「批量管理赛事 → 发布到公开库」里发布本地赛事。其他会员的 UID 可以直接在网页的「会员管理」里添加，不需要再进控制台。

> 如果公开库里已经有旧版发布的数据，需要先在控制台或脚本里给每条文档补上 `ownerUid` / `ownerName`（填原发布者的 UID 和显示名）；否则新的「仅发布者可修改」规则生效后，那些旧文档谁都不能编辑。

> CloudBase 体验环境资源点有限；长期使用建议升级个人版（约 19.9 元/月）。

### 发布历史赛事

`赛事数据/` 里的文件先按文件夹用「导入赛事」批量导入，再到「批量管理赛事」里勾选它们、点「发布到公开库」。随后在弹窗里选择已有文件夹，或选「＋ 新建文件夹…」输入新名称或路径（可以用 `/` 分层，例如 `NBPL赛事/2026秋季赛`），再点「确认发布」。这个名称会成为赛事的初始标签；管理员之后可以在公共页「整理」里修改标签和顺序。建议按从旧到新发布，赛事库会按标签分组，最近有更新的分组排在前面。

- 发布时会把你的 UID 记为 `ownerUid`，并显示发布者名字；本地赛事下拉和批量管理里会带「发布状态」标志。
- 发布成功后，这个本地赛事和公开记录建立链接，之后**自动双向同步**：
  - 本地修改（比分、备注、设置、锁、显示设置等）停顿约 0.7 秒后自动上传；不需要再点「发布到公开库」。同一浏览器的其他标签页会立即收到刷新通知，其他设备约 10–20 秒轮询到。
  - 在本地计分台里打开同一公开赛事编辑时，保存后会更新本地副本（本地空闲且没有未同步修改时）。
  - 在公共页里编辑时，改动照常保存到线上；本地副本会在下次切回本地计分台、激活该赛事时自动拉取。
  - 公共页轮询到新版本后会自动载入；正在输入或设置还没保存时会暂停自动刷新，提示「线上有新版本」。
  - 本地下拉 / 批量管理显示「🌐 已发布」「已隐藏」「⚠️ 同步暂停」三种状态。
  - 隐藏只影响访客可见性，发布者的修改仍会同步到隐藏记录，恢复公开后立即生效。
- 再次执行「发布到公开库」仍然有效：会更新你之前发布的那一条（按本地保存的链接，或按赛事 ID 找到自己的文档），也可以用来恢复线上已被删除的记录；如果同一个赛事 ID 已经被别的会员发布，不会覆盖。
- **两边都改了**：自动保存暂停并提示冲突，可选「载入线上版本」或「保留我的版本为副本」。选副本时，本地修改会变成一个新的本地赛事（不带链接），原赛事载入线上版本。
- **线上记录被删除**：自动暂停同步，本地数据原样保留，状态变成「⚠️ 同步暂停」；重新发布即可建立新记录。
- 未登录或在其他设备上时，本地修改只保存在浏览器；登录到发布者账号后会自动尝试同步。

### 同步与权限说明

- 未登录访客会自动建立一个匿名会话，仅用于读取公开数据；匿名 UID 不在白名单，无法写入。邮箱登录后会切换到正式账号。
- 本地链接赛事改完约 0.7 秒写入数据库；其他访客约 15–20 秒内看到，会员之间约 10–15 秒（页面需处于可见状态，切到后台会暂停轮询）。所有时间以网络和 CloudBase 实际响应为准。
- 公开赛事不是多人协作编辑：同一赛事由发布者一人维护。内容更新使用版本号（rev）乐观锁，冲突时不会静默覆盖；隐藏状态单独存放，不会改动内容版本。
- 账号支持邮箱 + 密码注册和密码登录。注册分两步：先验证邮箱，再设置密码；重发验证码不会清空已填写的密码。忘记密码时点密码登录下方的「忘记密码」，依次验证邮箱、设置新密码并登录，重置界面只从这个入口进入。以前用验证码创建、还没有密码的旧账号也可以用「忘记密码」设置密码；「验证码登录」仍然保留，不会修改原密码。
- 同一浏览器开多个标签页同时改同一个本地赛事时，localStorage 以最后一次写入为准；建议只在一个标签页里编辑。公开数据仍受 rev 乐观锁保护，另一个标签页的旧版本会提示冲突。
- 邮箱验证码可能进垃圾箱；会员数量建议控制在少数几个人，避免消耗过多邮件额度和数据库调用。
- 匿名登录必须保持开启：当前 CloudBase 环境下，未登录的数据库查询会报内部错误，网页会用匿名会话读取公开数据。如果关闭匿名登录，访客会看到「加载失败」。

## 使用提示

1. **排名分表请按当季官方规则核对一遍再开赛。** 规则每个赛季都会变，内置的默认值（官方 8 人制：单排 `2.5/1/0.5/0.5`，三排 `4/2/1/1`）只是一个起点，在「设置 → 排名分表」里可以逐格改。
2. **你自己新建 / 导入的数据存在浏览器本地**（localStorage）。换电脑、换浏览器、或者清理浏览器数据都会看不到之前的成绩，重要赛事请及时用「设置 → 导出本赛事」或顶栏「批量管理赛事」备份。公开赛事库里的数据存在 CloudBase，不受本地清理影响。
3. 单局同分排序按官方规则：单局总分 → 击败分 → 生存排名。伤害数据没有录入，排序链到此为止。
4. 设置改完要点击「保存设置」按钮保存，不然设置不会生效。没保存就想切到别的面板时，弹窗里点「确定」会先保存再切；点「取消」则丢弃改动直接切走（切回来还是原来的设置）。

## 数据说明

示例数据都在 [`赛事数据/测试数据/`](赛事数据/测试数据) 文件夹里，用顶栏「导入赛事」逐个载入。

- 第一赛段测试数据包含单排第一赛段决赛、三排第一赛段决赛、第一赛段第二轮败者组三个文件的数据，后续所有更新的数据都是单日数据。
- 真实赛事按赛季 / 赛事分文件夹存放；线上公开库的种子数据也来自这些文件夹，发布时保留文件夹名作为初始标签。

## 本地使用

下载 `index.html` 和整个 `assets/` 文件夹，保持目录结构，双击 `index.html` 用浏览器打开即可。不需要服务器、不需要构建、不需要联网。BP 英雄头像来自 `assets/heroes/`，官方队标来自 `assets/logos/`，评级素材来自 `assets/weapons/`、`assets/players/`；只复制 `index.html` 时功能仍可用，但头像、队标和评级素材会显示不出来。本地文件模式不会连接 CloudBase，公开赛事库入口会自动隐藏；需要公开赛事库时请使用线上网页。
